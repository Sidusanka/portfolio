Platform engineering

AKS upgrades and Flux CD migrations

Planned and ran AKS upgrades through versions 1.33, 1.34 and 1.35 alongside Flux CD migrations, with cluster stability as the goal.

My role
Upgrade planning and execution
Technologies
Azure Kubernetes Service · Flux CD · GitOps

Context

This work was part of my cloud platform role, supporting containerized workloads on Azure Kubernetes Service.

Problem

The Kubernetes version needed to move forward while keeping clusters stable and limiting disruption to services. The Flux CD setup also needed to be migrated.

My contribution

I planned and ran each AKS upgrade and carried out the Flux CD migrations.

Approach

I took AKS through successive versions, from 1.33 through 1.34 to 1.35. That made each version change a distinct step alongside the GitOps migration work.

Outcome

The work took AKS through 1.35 and included the Flux CD migrations. Keeping the clusters stable was the objective throughout the sequence.

Engineering takeaway

An upgrade plan should account for the Kubernetes version and the GitOps tooling that manages what runs on it.
