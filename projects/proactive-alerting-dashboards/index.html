Observability

Proactive Alerting & Infrastructure Observability

Production monitoring, Prometheus alerting and custom Grafana dashboards

My role
Alerting setup, dashboard development, and incident investigation
Technologies
Prometheus · Grafana Alloy · Grafana · Azure · Linux · Kubernetes · PromQL

Project overview

I helped improve monitoring for an enterprise cloud environment using Prometheus alerts and custom Grafana dashboards. The goal was to spot issues earlier and give engineers the metrics they needed during troubleshooting and incident response.

Problem statement

Manual checks can delay detection until a service is already affected. On virtual machines, application data, audit logs, and system logs can also consume disk space over time. Engineers needed continuous monitoring for conditions that required attention and a central place to inspect infrastructure and workload trends.

My contribution

I contributed to proactive alerting with Prometheus and Grafana Alloy, built and refined Grafana panels for infrastructure and application metrics, and used those metrics to support troubleshooting and incident investigations.

Technical implementation

  1. Infrastructure monitoring. I worked with a monitoring setup that collected and stored time-series metrics with Prometheus and displayed them in Grafana. The dashboards gave engineers a view of infrastructure health over time.
  2. Custom dashboards for edge workloads. I contributed to Grafana dashboards for Cloudflare Workers and other edge workloads. The panels showed request volumes, error rates, and latency percentiles. Filters let engineers narrow investigations to the relevant workload or environment.
  3. Proactive alerting. I helped set up alerts for infrastructure and application conditions that needed attention. Engineers could use the alert as a starting point, then check the associated metrics and trends in Grafana to investigate the cause.

Vault VM disk utilization

I set up disk monitoring for the VM hosting Vault. The Grafana dashboard showed total filesystem capacity, available space, utilization percentage, usage trends, and disk I/O activity. I configured a capacity alert to notify engineers when disk utilization crossed a threshold so they could review log retention or plan a storage increase.

Outcomes

The work gave engineers a clearer view of production infrastructure and application health, alerts for conditions that needed attention, and easier access to metrics during incident investigations. The dashboards also made it easier to inspect workload performance and traffic trends over time.

Engineering takeaway

An alert tells engineers when to investigate. A dashboard gives them the context to see when the behavior changed, which workloads were affected, and where to look next.
